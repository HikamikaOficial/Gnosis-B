## Architecture directives for the GNOSIS kernel

The strongest cross-repo convergences, stated as implementable kernel rules. Each directive is evidenced by multiple independent codebases that arrived at the same mechanism.

### 1. One canonical-bytes hash primitive under every chain

**Evidence:** bernstein (journal/WAL/work ledger/lineage share one `canonical_json` contract), opentraces (event_id = sha256 of canonical JSON including sequence + previous pointer), agent-capsule (canonical JSON → SHA3-256 → signed), reprise (`canonical_bytes`/`blob_hash`), agent-governance-toolkit (action identity = sha256 over key-sorted canonical JSON), dagger (recursive call digests).

**Rule:** The kernel defines exactly one primitive — `canonical_json = dumps(sort_keys=True, separators=(",",":")).encode("utf-8")` — and every hash in the system (journal entries, event ids, replay keys, action identities, approval bindings) derives from it. Document the contract so a third party can re-derive any hash by hand. Bernstein's warning applies: chain proliferation without a shared contract (five parallel event systems) is the failure mode to design out from day one.

### 2. Append-only, hash-chained journal with fail-closed recovery

**Evidence:** bernstein (`Journal._validate_chain_for_recovery` recomputes every hash from genesis, never trusts the tail), opentraces (CAS append to a git ref with bounded retry; content-addressed ids make replay order tamper-evident), agent-workspace-fabric (`WorkspaceEvent` append-only, per-workspace sequence counter, "no UPDATE/DELETE ever"), cezar (per-run NDJSON append + atomic tmp+rename index).

**Rule:** Kernel events are append-only rows with a per-scope monotonic sequence and a previous-hash pointer. On open, recompute the whole chain: a torn final line is a legitimate crash (keep the prefix); any interior corruption, sequence gap, or prev-hash break refuses to open and names the offending line. Never extend a chain from an unverified anchor.

### 3. State machine as a single frozen allow-list, with gates projected from it

**Evidence:** agent-workspace-fabric (`MappingProxyType` of `frozenset` transitions + `assert_transition` typed errors + documented salvage edges), symphony (orchestrator is the *only* component that mutates scheduling state; SPEC §7 vocabulary), bernstein (`approval_gate.py` derives approvable/completable sets from `tasks/lifecycle.py` constants so no transport gets weaker rules), spec-kit (phase-gated pipeline with typed handoffs), cezar (review park is a store-owned state, not a prompt convention).

**Rule:** Allowed Task transitions live once, in one importable kernel module, as immutable data. Every surface (CLI, MCP, HTTP, adapter) imports them; illegal transitions raise a typed error carrying `(from, to, allowed_next)`. The kernel is the *sole writer* of status — structurally, not by convention (AWF's guard-by-convention gap is the anti-pattern). Include explicit salvage edges for restart recovery, and gate spec→plan→tasks→implement phases as first-class states so no Task reaches implementation without a versioned spec artifact upstream.

### 4. Two-plane ownership: durable claims + ephemeral fenced leases

**Evidence:** beads (claim = CAS on a `row_lock` version token, in the same transaction that computed readiness; leases/heartbeats in a non-replicated ephemeral table; TTL reclaim with recovery events), agent-workspace-fabric (fencing epochs bumped as a SQL expression so stale workers are fenced on their next CAS), smithers (durable rewind lease with `checkStillHeld` re-checked *inside* the transaction), grit (`BEGIN IMMEDIATE` atomic check-then-set symbol leases — plus the fencing hole GNOSIS must close), cezar (repo-root promise-chain lease; account-scoped holds).

**Rule:** Separate history-worthy ownership transitions (durable, versioned) from liveness chatter (ephemeral leases + heartbeats that never enter history). Claims are conditional CAS on a version token rewritten by every ownership mutation, idempotent for same-actor retries, returning typed conflict data (holder, status) — never prose. Fencing epochs increment monotonically inside the claim transaction; expired leases are reclaimed by TTL sweep that repeats the expiry predicate at delete time. A lease stays bound to unresolved integration state — never release it just because a merge failed (grit's mistake).

### 5. Worktree lifecycle with provenance-gated destruction

**Evidence:** agent-workspace-fabric (per-repo bare mirror + per-workspace worktree, idempotent removal, cleanup that deliberately avoids blanket `reset --hard`), cezar (idempotent worktree creation, never deletes non-empty unregistered dirs, autosave refuses mid-merge/conflict-marker states and tags its reason), orca (`BranchMode.Created` gate — only branches orca minted may be auto-deleted; resume header validated as hostile input before any destructive git action), grit (merge under PID-liveness-checked lock, preserves branch+worktree on failure), bernstein (content-addressed snapshots under refs, fork refuses on sha mismatch).

**Rule:** The kernel mints per-task worktrees/branches and records that provenance at creation time; destruction is gated on "did the kernel mint this". Creation is idempotent with reattach paths; non-empty unregistered directories are recoverable work, never deleted. Autosave commits carry a reason tag and refuse conflict-marker states — losing a recovery point beats poisoning the branch. Any resume/recovery header is validated as hostile input (ref-shape checks, protected-branch floor, cross-checks) before any destructive operation; invalid state is a hard abort, and corrupt-state is distinguished from absent-state.

### 6. Review convergence: signal ∧ evidence, tri-state rounds, stalemate fingerprints, nothing-lost ledger

**Evidence:** ralphex (ALL_TASKS_DONE discarded if unchecked boxes remain; DONE means "zero issues this round", not "I finished fixing"; git HEAD+diff fingerprint stalemate counter), orca (bounded review loop with hard caps, per-severity confidence gates, and a `GateLedger` where every gated-out or declined finding is carried and printed at exit), cezar (review park state the agent cannot bypass; done-signals parsed only from the agent's own turn text), agent-arena (independent generation → evidence checking → blind judging, dissent preserved in the synthesis artifact).

**Rule:** An agent's DONE claim never closes a Task. The kernel re-checks a durable artifact (plan checkboxes, git HEAD/diff fingerprint) and downgrades signal-without-evidence to continue-with-warning. Rounds are tri-state: clean round → converged; fixed-something → schedule another independent verification round; can't-fix → typed failure. A stalemate counter over repo-state fingerprints (N consecutive unchanged rounds → `STALEMATE`) is a kernel circuit breaker, resets on change, and never counts when evidence collection itself failed. Every finding held back by a gate is carried in a ledger and surfaced at every loop exit — the loop cannot silently drop evidence. Dissent from independent reviewers is preserved in the evidence artifact.

### 7. Strict replay as default; write-ahead intent before side effects

**Evidence:** bernstein (`DeterministicStore` — replay miss aborts, never silently falls through to a live model; per-key FIFO preserves call order and multiplicity; response-determining params folded into the key), reprise (occurrence-aware Nth-identical-request matching from a content-addressed SQLite blob store; strict-mode `ReplayMiss`), smithers (journal row with status `intended` + {sideEffect, idempotent, hasRevert, idempotencyKey} persisted *before* any tool executes; rewind safety becomes a decidable query), dagger (same recipe → same digest → memoized result), catacomb (recorded evidence as regression fixtures).

**Rule:** Record every LLM/tool call keyed by a content hash of its response-determining parameters (model, provider, temperature, max_tokens, effort). Replay is occurrence-aware and strict: a miss is an abort; live fall-through is an explicit opt-in. Before any side-effecting tool executes, persist an `intended` journal row with side-effect provenance flags, so rewind/fork/compensation safety is answered by querying the journal, never by guessing. Golden runs become regression fixtures.

### 8. Fail-closed, stateless policy verdicts; honesty about enforcement

**Evidence:** agent-governance-toolkit (ACS: complete JSON snapshot in → exactly one of allow/deny/warn/escalate/transform out; *every* runtime failure collapses to deny with a reserved `runtime_error:*` reason policies may not emit; unconfigured intervention point denies; undeclared tool denies; approvals bound to the exact action hash), agentjail (verdicts over parsed command intent — program/flags/resolved paths — with rule_id provenance), nono (kernel-enforced deny-by-default as the floor beneath advisory hooks), orca (enforcement honesty matrix: every backend restriction classified Hard/SandboxApprox/PromptOnly/Ignored, machine-checked in tests), opentraces (single three-way egress predicate; `unknown` is never coerced to safe).

**Rule:** The kernel's Policy Engine is a pure, stateless function: adapters build a complete snapshot per intervention point; the engine returns exactly one verdict; every internal failure returns deny with a reserved reason namespace, so a deny-by-error is always distinguishable from a policy deny. Missing bindings and undeclared tools fail closed — configuration gaps are never consent. NEEDS_HUMAN escalations bind approval to the sha256 action identity of exactly what was evaluated (anti-TOCTOU). Decisions key on structured, parsed intent — never string pattern-matching with hardcoded bypass lists. And per adapter, maintain a machine-checked enforcement matrix recording whether each restriction is mechanically enforced, sandbox-approximated, prompt-only, or ignored — the kernel's least-privilege decisions consume honest data.

### 9. Typed failure taxonomy end-to-end; rate limits as park states; recovery as reconcile

**Evidence:** cezar (evidence-ordered usage-limit parsing that records *which* evidence shape carried each classification and refuses to guess; durable `autoResumeAt`; deadline holds vs in-flight holds keyed by runner:credential; boot re-adoption that revives through the normal queue path or fails loudly), smithers (`waiting-quota` durable park state with `resetAtMs`; startup crash recovery from pre-mutation audit rows), ralphex (three-tier retry/limit/error taxonomy with signal-suppressed retries), agent-workspace-fabric (reason codes flowing exception → log → append-only event → failure taxonomy → scheduler policy, with a generated catalog as the drift gate), symphony (distinct terminal reasons Failed/TimedOut/Stalled/Canceled because "retry logic and logs differ"; reconcile-before-dispatch on every poll tick), beads (typed `ClaimConflictError` carrying holder+status).

**Rule:** Failures are typed at the adapter boundary (structured exit/frame codes first; prose parsing only as a last-resort enricher, with the evidence grade recorded on every classification). Reason codes flow unchanged from exception to append-only event to scheduler policy — implementing GNOSIS rules 5–7 (`RATE_LIMITED != FAIL_CODE`; `FAIL_INFRA` doesn't penalize the agent). `RATE_LIMITED` is a durable park state carrying a reset timestamp, with account-scoped holds distinguishing "window known shut — block everything on this credential" from "one resume is probing — block only new work". Recovery is reconcile, not restore: durable state on the record, volatile timers rebuilt idempotently on every scheduler pump, plus a boot sweep that re-adopts every stranded run through normal paths or fails it loudly — never leaving a ghost.

## Contradictions and open questions

1. **Fail-open vs fail-closed evidence sealing.** Bernstein's completion evidence gate is deliberately fail-open ("Evidence sealing must NEVER block… any error is caught and swallowed") and agent-capsule's adapters are fail-open by design; ACS, opentraces' egress predicate, and GNOSIS Rule 2 demand fail-closed. The tension is availability (don't lose finished work over a sealing bug) vs integrity (no DONE without evidence). GNOSIS's constitution settles the default (fail closed), but the open question is the recovery path: what evidence would settle the cost is a chaos test measuring, under injected sealing failures, the rate of lost-but-recoverable work in a fail-closed design vs the rate of falsely-closed Tasks in a fail-open one.

2. **Loop exhaustion semantics.** Ralphex soft-continues on max-iterations ("continuing…") and reads unchanged HEAD as convergence even when the reviewer may simply have failed to act; orca hard-caps with a nothing-lost ledger; AWF's PR monitor has *no* iteration/wall-clock terminal gate at all, delegating livelock to human-notification gates (in tension with GNOSIS Rule 8). Evidence to settle: measure, on a replayed corpus of review loops, how often exhaustion-with-flow-through ships unconverged defects vs how often hard-stop + NEEDS_HUMAN merely delays a run that would have converged.

3. **Advisory vs enforced ownership.** Grit's symbol locks are pure convention (`cmd_done` commits everything touched and never diffs changes against held locks); orca enforces "fan-out can read, never commit" at compile time via capability tokens; the deep analyses converge on a kernel merge gate (diff hunks mapped to AST symbols, `FAIL_POLICY` if changed-symbols ⊄ claimed-symbols) that no surveyed repo actually implements. Evidence to settle: a multi-agent conflict-injection benchmark counting how many unclaimed-symbol mutations reach merge under advisory-only vs gate-enforced ownership, and the gate's false-positive rate on legitimate refactors.

4. **Where failure classification lives.** Cezar and ralphex classify failures by regex over provider prose at the terminal error; AWF, ACS, and symphony type failures structurally at the boundary. Cezar's evidence-graded prose parsing is the best of its kind, but it is inherently provider-version-fragile. Evidence to settle: a per-backend audit of what fraction of real failure events carry structured codes (exit codes, JSON frames) vs prose-only — if structured coverage is high, prose parsing is demoted to enricher; where it is low, cezar's evidence-ordered recognizers are the fallback.

5. **In-band signals vs kernel-owned state.** Ralphex matches `<<<RALPHEX:...>>>` anywhere in output (a model *quoting* the marker triggers it, defended only by prompt exhortation); cezar narrows to line-anchored markers parsed only from the agent's own turn text, never tool output; cezar's review gate goes further — the state is store-owned and no marker can bypass it. Evidence to settle: marker-quoting injection tests against each scheme; the survey already strongly suggests kernel-owned out-of-band state wins, with in-band markers acceptable only as hints that never directly transition state.

6. **Destructive teardown discipline.** Orca performs `git reset --hard` + gated `clean` in failure teardown (safe only because its recovery header is validated as hostile first); cezar and AWF deliberately refuse blanket resets, preferring autosave commits and idempotent reattach. GNOSIS Rule 27 forbids reset-as-shortcut, but orca shows a disciplined, validated reset can make resume-in-place trivial. Evidence to settle: crash-injection runs comparing recovery-loss incidents (work destroyed by teardown) vs poisoned-workspace incidents (stale state corrupting the resumed run) under each discipline.

7. **Storage substrate weight vs scale.** Beads (Dolt, 60+ migrations, proxy daemon) and AWF (Postgres + Compose stacks) carry heavy substrates for semantics that cezar, reprise, grit, and smithers deliver on SQLite/plain files; beads' claim scan is also deliberately unbounded over the ready set (acknowledged in claim.go). SQLite-V1 is the GNOSIS ADR baseline. Evidence to settle: a scheduler benchmark at GNOSIS's actual scale envelope (hundreds to low-thousands of Tasks) measuring whether the materialized-`is_blocked` + CAS-claim pattern on SQLite holds up before any heavier substrate is even discussed.

8. **Rate-limit hold granularity.** Cezar's two-hold account model (deadline holds block everything on a credential; in-flight holds block only new work — each kind fixed a real bug in opposite directions) vs smithers' simpler single `waiting-quota` park. Evidence to settle: reproduce resume-stampede and resume-deadlock scenarios with multiple concurrent runs sharing one credential; if both reproduce, the two-hold model is required, not optional.

- **GNOSIS takeaway:** Two directly transferable invariants for the GNOSIS event/evidence pipeline: declare mutation capability per consumer and clone only when a mutator shares data, and always start sinks before sources (reverse-topological startup) so no event is emitted into an unready pipeline.
